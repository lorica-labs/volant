`volant vault` tut, was `ansible-vault encrypt`, `decrypt`, `view`, `create`, `edit` und `rekey` tun, auf denselben Dateien, mit denselben Meldungen und denselben Exit-Codes. `encrypt_string` gibt es noch nicht. Einzelheiten stehen unter [Vault](/de/docs/variables/vault/#dateien-verschlüsseln-und-anzeigen) und [Vault](/de/docs/variables/vault/#dateien-anlegen-bearbeiten-und-neu-verschlüsseln).

```sh
volant vault encrypt [FILE...] [--output FILE] [--encrypt-vault-id ID] [OPTIONS]
volant vault decrypt [FILE...] [--output FILE] [OPTIONS]
volant vault view [FILE...] [OPTIONS]
volant vault create [--encrypt-vault-id ID] [--skip-tty-check] FILE [OPTIONS]
volant vault edit FILE... [OPTIONS]
volant vault rekey FILE... [--new-vault-password-file FILE | --new-vault-id ID] [OPTIONS]
```

`OPTIONS` sind `--vault-id`, `--vault-password-file` (auch `--vault-pass-file`), `-J`/`--ask-vault-pass` und `-v`, unter [Vault](/de/docs/reference/cli/#vault) beschrieben. Ohne eine davon und ohne die Einstellung `vault_password_file` fragt der Befehl nach dem Passwort.

<Option name="--output" arg="FILE">
  Schreibt das Ergebnis dorthin und lässt die Quelle unverändert. `-` ist die Standardausgabe. Damit wird nur eine Eingabedatei akzeptiert, sonst ist der Exit-Code 5.
</Option>

<Option name="--encrypt-vault-id" arg="ID" config="[defaults] vault_encrypt_identity" env="ANSIBLE_VAULT_ENCRYPT_IDENTITY">
  Die Vault-ID, die `encrypt`, `create` und `rekey` verwenden. `encrypt` und `create` verlangen sie, wenn mehr als eine `--vault-id` angegeben wird. `edit` akzeptiert sie und ignoriert sie: Eine Datei behält ihr eigenes Label.
</Option>

<Option name="--skip-tty-check">
  `create` öffnet den Editor auch dann, wenn die Standardausgabe kein Terminal ist. Ohne sie verweigert `create` mit Exit-Code 5.
</Option>

<Option name="--new-vault-password-file, --new-vault-id" arg="FILE | LABEL@SOURCE">
  Das neue Geheimnis für `rekey`. Geben Sie eine der beiden an. Ohne beide fragt `rekey` danach.
</Option>
