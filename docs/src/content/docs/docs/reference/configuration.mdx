Volant reads the same `ansible.cfg` as `ansible-playbook`, and stops at the first file it finds:

<Steps>

1. the file named by `ANSIBLE_CONFIG`
2. `./ansible.cfg`
3. `~/.ansible.cfg`
4. `/etc/ansible/ansible.cfg`

</Steps>

Volant skips `./ansible.cfg` when the working directory is writable by other users (mode bit `o+w`), as `ansible-playbook` does. Another local user could have put the file there. The sticky bit and the owner of the directory change nothing. Volant prints `[WARNING]: Ansible is being run in a world writable directory (...), ignoring it as an ansible.cfg source.` on standard error and continues with the next file. A file named by `ANSIBLE_CONFIG` is read whatever the mode of the working directory.

For each setting, the environment variable beats the file, and the command-line option beats both. Keys Volant does not use are ignored, as Ansible ignores the ones it does not use.

A file that exists but cannot be read is skipped, and the run continues with the defaults. Volant prints a warning first, which Ansible does not: a file you wrote that the process cannot open deserves a line, and a warning does not change the exit code.

## [defaults]

<Option name="inventory" id="defaults-inventory" flag="-i" env="ANSIBLE_INVENTORY">
  The inventory sources, as a comma-separated list. See [Inventories](/docs/hosts/inventories/#sources).
</Option>

<Option name="timeout" id="defaults-timeout" default="10" flag="-T" env="ANSIBLE_TIMEOUT">
  Seconds to wait for a connection. It becomes `ConnectTimeout` on the `ssh` command line.
</Option>

<Option name="remote_user" id="defaults-remote-user" flag="-u" env="ANSIBLE_REMOTE_USER">
  The user to log in as. Without it, `ssh` picks one.
</Option>

<Option name="private_key_file" id="defaults-private-key-file" flag="--private-key" env="ANSIBLE_PRIVATE_KEY_FILE">
  The private key `ssh` authenticates with.
</Option>

<Option name="host_key_checking" id="defaults-host-key-checking" default="true" env="ANSIBLE_HOST_KEY_CHECKING">
  With it on, an unknown host key makes the host unreachable. With it off, Volant adds `StrictHostKeyChecking=no` and `UserKnownHostsFile=/dev/null`, so an unknown key is accepted and not recorded.
</Option>

<Option name="remote_tmp" id="defaults-remote-tmp" default="~/.ansible/tmp" env="ANSIBLE_REMOTE_TMP">
  The directory on each host that holds the [agent cache](/docs/hosts/connections/#the-agent-cache).
</Option>

<Option name="forks" id="defaults-forks" default="5" flag="-f" env="ANSIBLE_FORKS">
  How many hosts a play works on at once. Zero or a value that is not a number is rejected before the run starts. Playbooks read the current value as `ansible_forks`.
</Option>

<Option name="async_dir" id="defaults-async-dir" default="~/.ansible_async" env="ANSIBLE_ASYNC_DIR">
  The directory on each host that holds the status files of [async tasks](/docs/playbooks/how-a-play-runs/#async-tasks). `ansible_async_dir` overrides it.
</Option>

<Option name="enable_task_debugger" id="defaults-enable-task-debugger" default="false" env="ANSIBLE_ENABLE_TASK_DEBUGGER">
  Open the [debugger](/docs/playbooks/how-a-play-runs/#the-debugger) after every failed or unreachable task.
</Option>

<Option name="show_task_path_on_failure" id="defaults-show-task-path-on-failure" default="false" env="ANSIBLE_SHOW_TASK_PATH_ON_FAILURE">
  Print `task path: <file>:<line>` before the `fatal:` line of a failed task. From `-vv` the line already follows every task banner, so this changes nothing there. A loop item's `failed:` line and an unreachable host get no path line. As in Ansible, `y`, `yes`, `on`, `true`, `t` and `1` turn it on in any case, and any other word, an empty variable included, leaves it off.
</Option>

<Option name="force_color" id="defaults-force-color" default="false" env="ANSIBLE_FORCE_COLOR">
  Colour the output even when it is not a terminal, as CI logs need. It wins over `nocolor`, `ANSIBLE_NOCOLOR` and `NO_COLOR`; only `--no-color` wins over it. In a diff, only the lines Ansible's `difflib` made from `before` and `after` are coloured.
</Option>

<Option name="nocolor" id="defaults-nocolor" default="false" env="ANSIBLE_NOCOLOR">
  Never colour the output. `force_color` wins over it.
</Option>

<Option name="deprecation_warnings" id="defaults-deprecation-warnings" default="true" env="ANSIBLE_DEPRECATION_WARNINGS">
  Print the `[DEPRECATION WARNING]` notices and the line that tells how to stop them. Set to `False` to print neither.
</Option>

<Option name="localhost_warning" id="defaults-localhost-warning" default="true" env="ANSIBLE_LOCALHOST_WARNING">
  Warn when the inventory holds no host, so that only the implicit `localhost` is left. `all` does not match that host.
</Option>

<Option name="force_handlers" id="defaults-force-handlers" default="false" flag="--force-handlers" env="ANSIBLE_FORCE_HANDLERS">
  Run notified handlers even on hosts that failed.
</Option>

<Option name="duplicate_dict_key" id="defaults-duplicate-dict-key" default="warn" env="ANSIBLE_DUPLICATE_YAML_DICT_KEY">
  What a YAML key written twice in one mapping gets: `warn` keeps the last value and prints where the second key is, `error` refuses the file, `ignore` keeps the last value and says nothing.
</Option>

<Option name="facts_modules" id="defaults-facts-modules" default="smart" env="ANSIBLE_FACTS_MODULES">
  The fact modules the play's fact gathering runs, `smart` (`setup`) unless set. A literal list in the plays, their tasks or the inventory (`ansible_facts_modules`) is read too; a module named only by a template cannot be run.
</Option>

<Option name="show_custom_stats" id="defaults-show-custom-stats" default="false" env="ANSIBLE_SHOW_CUSTOM_STATS">
  Print the statistics that `set_stats` collected after the recap.
</Option>

<Option name="stdout_callback" id="defaults-stdout-callback" default="default" env="ANSIBLE_STDOUT_CALLBACK">
  The callback that prints the run. `default` prints the banners, a line per result and the recap. `minimal` prints each result as the ad hoc command does, `host | CHANGED | rc=0 >>` and the output for a command, `host | SUCCESS => ` and the result as JSON otherwise, with no banner, no recap and no line per loop item. `oneline` prints the same results on one line each; ansible-core 2.19.12 deprecates it and Volant prints its warning once on standard error. `tree` prints nothing on standard output. The `ansible.builtin.` names work too. Any other name, such as the collections' `json` and `yaml`, stops the run before the first play with `[ERROR]: Could not load '<name>' callback plugin.` and exit code 1.
</Option>

<Option name="callbacks_enabled" id="defaults-callbacks-enabled" env="ANSIBLE_CALLBACKS_ENABLED">
  More callbacks to run beside the stdout one, as a comma-separated list. Volant runs none of them yet: each name prints `[WARNING]: Skipping callback plugin '<name>', unable to load` and the run goes on. `volant.compat.record`, which [records ansible-playbook's runs](/docs/reference/recording/), is skipped without a warning.
</Option>

<Option name="callback_plugins" id="defaults-callback-plugins" env="ANSIBLE_CALLBACK_PLUGINS">
  More directories to look for callback plugins in, separated by `:`. Volant reads the setting but loads only its own callbacks.
</Option>

<Option name="bin_ansible_callbacks" id="defaults-bin-ansible-callbacks" default="false" env="ANSIBLE_LOAD_CALLBACK_PLUGINS">
  Whether the ad hoc command loads the callbacks above. Off, it prints through `minimal`, or `oneline` with `-o`, whatever `stdout_callback` says. See [the ad hoc command](/docs/reference/cli/adhoc/).
</Option>

<Option name="vault_password_file" id="defaults-vault-password-file" flag="--vault-password-file" env="ANSIBLE_VAULT_PASSWORD_FILE">
  A file holding the vault password, or an executable that prints it. The environment variable replaces the file's value, and the command line adds to whichever won. See [Vault](/docs/variables/vault/).
</Option>

<Option name="vault_identity_list" id="defaults-vault-identity-list" flag="--vault-id" env="ANSIBLE_VAULT_IDENTITY_LIST">
  Comma-separated vault identities, each written `label@source` where the source is a file, an executable or `prompt`. The environment variable replaces the file's list, and the command line adds to whichever won.
</Option>

<Option name="vault_encrypt_identity" id="defaults-vault-encrypt-identity" flag="--encrypt-vault-id" env="ANSIBLE_VAULT_ENCRYPT_IDENTITY">
  The vault id `volant vault encrypt` uses when `--encrypt-vault-id` is not given. See [Vault](/docs/variables/vault/#encrypting-and-viewing-files).
</Option>

<Option name="editor" id="defaults-editor" env="ANSIBLE_EDITOR, EDITOR">
  The editor `volant vault create` and `edit` run. The last variable set wins, then the file, then `vi`. See [Vault](/docs/variables/vault/#creating-editing-and-rekeying-files).
</Option>

<Option name="local_tmp" id="defaults-local-tmp" default="~/.ansible/tmp" env="ANSIBLE_LOCAL_TEMP">
  Where `volant vault create` and `edit` keep the private copy the editor works on.
</Option>

<Option name="pager" id="defaults-pager" default="less" env="ANSIBLE_PAGER, PAGER">
  The program `volant vault view` pipes through on a terminal. The last variable set wins, then the file.
</Option>

<Option name="roles_path" id="defaults-roles-path" default="~/.ansible/roles:/usr/share/ansible/roles:/etc/ansible/roles" env="ANSIBLE_ROLES_PATH">
  Where roles are looked for, after `<playbook_dir>/roles` and before `<playbook_dir>` itself. See [Roles](/docs/playbooks/roles/#finding-a-role).
</Option>

<Option name="collections_path" id="defaults-collections-path" default="~/.ansible/collections:/usr/share/ansible/collections" env="ANSIBLE_COLLECTIONS_PATH">
  Also read as `collections_paths`, and from `ANSIBLE_COLLECTIONS_PATHS`, which wins over `ANSIBLE_COLLECTIONS_PATH`. Where a three-part role name such as `acme.demo.hello` is looked for. A collection's modules are found by the controller's ansible-core, in the paths it is configured with: see [Modules from collections](/docs/internals/python/#modules-from-collections).
</Option>

<Option name="gathering" id="defaults-gathering" default="implicit" env="ANSIBLE_GATHERING">
  `implicit`, `explicit` or `smart`. See [The fact cache](/docs/hosts/inventories/#gathering).
</Option>

<Option name="fact_caching" id="defaults-fact-caching" default="memory" env="ANSIBLE_CACHE_PLUGIN">
  `memory` keeps facts for the run, `jsonfile` keeps them between runs. See [The fact cache](/docs/hosts/inventories/#the-fact-cache).
</Option>

<Option name="fact_caching_connection" id="defaults-fact-caching-connection" env="ANSIBLE_CACHE_PLUGIN_CONNECTION">
  The directory of the `jsonfile` cache.
</Option>

<Option name="fact_caching_timeout" id="defaults-fact-caching-timeout" default="86400" env="ANSIBLE_CACHE_PLUGIN_TIMEOUT">
  Seconds a cached entry stays fresh. `0` never expires.
</Option>

<Option name="fact_caching_prefix" id="defaults-fact-caching-prefix" env="ANSIBLE_CACHE_PLUGIN_PREFIX">
  Put in front of each cache file name.
</Option>

## [inventory]

<Option name="enable_plugins" id="inventory-enable-plugins" default="host_list, script, auto, yaml, ini, toml" env="ANSIBLE_INVENTORY_ENABLED">
  The inventory plugins to try, in order. See [the plugin chain](/docs/hosts/inventories/#the-plugin-chain).
</Option>

<Option name="ignore_extensions" id="inventory-ignore-extensions" default=".pyc, .pyo, .swp, .bak, ~, .rpm, .md, .txt, .rst, .orig, .cfg, .retry" env="ANSIBLE_INVENTORY_IGNORE">
  File extensions skipped when a directory is read. A value replaces the default list. `[defaults] inventory_ignore_extensions` is read too.
</Option>

<Option name="ignore_patterns" id="inventory-ignore-patterns" env="ANSIBLE_INVENTORY_IGNORE_REGEX">
  Regular expressions for file names skipped when a directory is read. `[defaults] inventory_ignore_patterns` is read too.
</Option>

<Option name="unparsed_is_failed" id="inventory-unparsed-is-failed" default="false" env="ANSIBLE_INVENTORY_UNPARSED_FAILED">
  Fail the run when no source could be read.
</Option>

<Option name="any_unparsed_is_failed" id="inventory-any-unparsed-is-failed" default="false" env="ANSIBLE_INVENTORY_ANY_UNPARSED_IS_FAILED">
  Fail the run at the first source no plugin could read.
</Option>

<Option name="export" id="inventory-export" default="false" env="ANSIBLE_INVENTORY_EXPORT">
  Make `volant inventory` keep each variable where it is set, as `--export` does. `--export` turns it on for one run; nothing turns it off from the command line, as in `ansible-inventory`. See [the inventory command](/docs/reference/cli/inventory/).
</Option>

## [inventory_plugin_script]

<Option name="always_show_stderr" id="inventory-plugin-script-always-show-stderr" default="true" env="ANSIBLE_INVENTORY_PLUGIN_SCRIPT_STDERR">
  Show what a successful inventory script wrote on standard error as an `[ERROR]:` line. With `false`, only the standard error of a script that fails is shown.
</Option>

<Option name="become" id="privilege-escalation-become" default="false" flag="-b" env="ANSIBLE_BECOME">
  Escalate by default. Playbook keywords and host variables take priority, see [Privilege escalation](/docs/hosts/connections/#which-setting-wins).
</Option>

<Option name="become_user" id="privilege-escalation-become-user" default="root" flag="--become-user" env="ANSIBLE_BECOME_USER">
  The user to escalate to.
</Option>

<Option name="become_method" id="privilege-escalation-become-method" default="sudo" flag="--become-method" env="ANSIBLE_BECOME_METHOD">
  The escalation method: `sudo` or `su`. Other methods stop the run before it starts.
</Option>

<Option name="become_exe" id="privilege-escalation-become-exe" env="ANSIBLE_BECOME_EXE">
  The program to run instead of `sudo` or `su`.
</Option>

<Option name="become_flags" id="privilege-escalation-become-flags" env="ANSIBLE_BECOME_FLAGS">
  The flags given to that program, in place of `-H` for `sudo` and of none for `su`. A blank value gives no flags at all.
</Option>

## [ssh_connection]

<Option name="usetty" id="ssh-connection-usetty" default="true" env="ANSIBLE_SSH_USETTY">
  Give `raw`, `script` and the commands a module plugin such as `reboot` sends without input a terminal, as `ssh -tt` does. Set it to `False` when a `sudoers` rule has `requiretty` or a command prints control characters on a terminal. The host variable `ansible_ssh_use_tty` wins over the environment variable, and the environment variable over the file. A word other than `y`, `yes`, `on`, `true`, `t` and `1` reads as off.
</Option>

## [volant]

Ansible ignores this section, so one `ansible.cfg` can carry it and still drive both engines. `ansible-config validate` is the exception, see [Cross-host batching](/docs/hosts/batching/#turning-it-on).

<Option name="batching" id="volant-batching" default="false" env="VOLANT_BATCHING">
  Off by default. With `batching = true`, a host moves on to its next tasks without waiting for the other hosts, except in front of a task whose text reads another host (`hostvars`, `ansible_play_hosts`, `delegate_to`, a template or variable that does). A dependency the playbook does not spell, such as a service another host is still installing or a file on a host named literally, is not waited for. Turn it on only for plays whose hosts do not depend on each other that way. See [Cross-host batching](/docs/hosts/batching/).
</Option>

<Option name="native_modules" id="volant-native-modules" default="true" env="VOLANT_NATIVE_MODULES">
  Let the agent answer a task with its native version of the module, when the task's arguments stay within what that version implements. With `false`, every task goes to ansible-core's Python module, and `setup` too, which is how to compare the two paths on a real run. The value is read as ansible-core reads a boolean, and a word it does not know stops the run with exit code 5. See [Native modules](/docs/internals/python/#native-modules).
</Option>

<Option name="runtime" id="volant-runtime" default="auto" env="VOLANT_RUNTIME">
  Where the controller's Python comes from. `auto` uses `VOLANT_PYTHON`, then the managed runtime when installed, then the active virtual environment and `python3`, and installs the managed runtime when none of them works. `managed` uses `VOLANT_PYTHON` or the managed runtime only, and installs it when it is missing. `system` never uses or installs the managed runtime. Any other word stops the run with exit code 5. See [The managed runtime](/docs/reference/runtime/).
</Option>

<Option name="ssh_control_master" id="volant-ssh-control-master" default="true" env="VOLANT_SSH_CONTROL_MASTER">
  Share one OpenSSH connection between all the `ssh` runs of an inventory host. With `false`, each link and probe opens its own connection. See [One connection per host](/docs/hosts/connections/#one-connection-per-host).
</Option>

<Option name="shadow_runs" id="volant-shadow-runs" default="5">
  How many clean replays in a row [`volant shadow status`](/docs/reference/cli/shadow/#the-ledger-and-the-verdict) wants of a playbook before it calls it `ready`. A whole number of at least 1; anything else stops the run with exit code 5. See [Switch without risk](/docs/start/switch-without-risk/).
</Option>

<Option name="shadow_coverage" id="volant-shadow-coverage" default="0.9">
  The share of a playbook's tasks those replays must have compared, from 0 to 1, before `volant shadow status` calls it `ready`. Anything else stops the run with exit code 5.
</Option>

<Option name="host_named_paths" id="volant-host-named-paths" default="allow" env="VOLANT_HOST_NAMED_PATHS">
  Sets what `template`, `copy`, `script`, `unarchive` and `assemble` do with a controller `src` that a managed host named, and where a `fetch` may write a `dest` that a host named: `allow`, `contained` or `refuse`. The default is `allow`, which behaves as ansible-core does, and any other word stops the run with exit code 5. See [A source file a managed host named](/docs/internals/action-plugins/#a-source-file-a-managed-host-named) for what each word does.
</Option>

<Option name="host_named_dest_dirs" id="volant-host-named-dest-dirs" default="unset" env="VOLANT_HOST_NAMED_DEST_DIRS">
  A colon-separated list of absolute controller directories under which `fetch` may write a `dest` that a managed host named. An entry that is relative, uses `~` or `..`, or is `/` stops the run with exit code 5. See [A dest a managed host named](/docs/internals/action-plugins/#a-dest-a-managed-host-named) for the rules.
</Option>
