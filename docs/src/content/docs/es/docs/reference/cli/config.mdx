`volant config` ejecuta el `ansible-config` de ansible-core 2.19.12 con el intérprete que Volant elige para una ejecución de playbook, así que funciona sin ansible-core instalado. Imprime lo que imprime el script y sale con el mismo código.

```sh
volant config [ARGS...]
```

Cada argumento va a `ansible-config` sin cambios, incluidos `-h` y `--version`. Por ejemplo `volant config dump --only-changed`, `volant config list`, `volant config view`, `volant config validate -c ansible.cfg` y `volant config init`.

El intérprete, el entorno, el terminal, el código de salida y `--version` funcionan como en [`volant doc`](/es/docs/reference/cli/doc/). `ansible-config` encuentra `ansible.cfg` por sí mismo, con las reglas habituales, así que no hay que pasarle nada.

## La ruta de colecciones

Cuando el runtime tiene un directorio `collections/`, Volant da a la herramienta un `ANSIBLE_COLLECTIONS_PATH` que termina con él, así que `volant config dump` muestra `COLLECTIONS_PATHS` como fijado por el entorno (`env: ANSIBLE_COLLECTIONS_PATH`), incluso cuando el valor viene de `collections_path` en `ansible.cfg`. Un `ansible-config` ejecutado directamente no lo mostraría.

## La sección `[volant]`

`[volant]` es la sección propia de Volant, que ansible-core no conoce. `volant config` no muestra sus ajustes: `volant runtime status` sí. `volant config validate` informa de la sección como lo hace `ansible-config validate`:

```
[ERROR]: Found unknown section 'volant' in '<dir>/ansible.cfg.
```

La comilla después del nombre del archivo también falta en el mensaje de ansible-core, y el código de salida es 1. Consulta [Configuración](/es/docs/reference/configuration/#volant).
