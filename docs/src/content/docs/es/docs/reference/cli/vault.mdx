`volant vault` hace lo que hacen `ansible-vault encrypt`, `decrypt`, `view`, `create`, `edit` y `rekey`, sobre los mismos archivos, con los mismos mensajes y los mismos códigos de salida. `encrypt_string` todavía no existe. [Vault](/es/docs/variables/vault/#cifrar-y-ver-archivos) y [Vault](/es/docs/variables/vault/#crear-editar-y-recifrar-archivos) dan los detalles.

```sh
volant vault encrypt [FILE...] [--output FILE] [--encrypt-vault-id ID] [OPTIONS]
volant vault decrypt [FILE...] [--output FILE] [OPTIONS]
volant vault view [FILE...] [OPTIONS]
volant vault create [--encrypt-vault-id ID] [--skip-tty-check] FILE [OPTIONS]
volant vault edit FILE... [OPTIONS]
volant vault rekey FILE... [--new-vault-password-file FILE | --new-vault-id ID] [OPTIONS]
```

`OPTIONS` son `--vault-id`, `--vault-password-file` (también `--vault-pass-file`), `-J`/`--ask-vault-pass` y `-v`, descritas en [Vault](/es/docs/reference/cli/#vault). Sin ninguna de ellas, y sin el ajuste `vault_password_file`, el comando pide la contraseña.

<Option name="--output" arg="FILE">
  Escribe el resultado ahí y deja intacto el origen. `-` es la salida estándar. Con esta opción solo se acepta un archivo de entrada; si no, el código de salida es 5.
</Option>

<Option name="--encrypt-vault-id" arg="ID" config="[defaults] vault_encrypt_identity" env="ANSIBLE_VAULT_ENCRYPT_IDENTITY">
  El id de vault que usan `encrypt`, `create` y `rekey`. `encrypt` y `create` lo exigen cuando se da más de un `--vault-id`. `edit` lo acepta y lo ignora: un archivo conserva su propia etiqueta.
</Option>

<Option name="--skip-tty-check">
  `create` abre el editor aunque la salida estándar no sea un terminal. Sin ella, `create` se niega con el código de salida 5.
</Option>

<Option name="--new-vault-password-file, --new-vault-id" arg="FILE | LABEL@SOURCE">
  El nuevo secreto para `rekey`. Da uno de los dos. Sin ninguno, `rekey` lo pide.
</Option>
