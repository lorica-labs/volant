`volant galaxy` 接受 ansible-core 2.19.12 中 `ansible-galaxy` 的子命令和选项，为它编写的脚本和 CI 任务无需修改命令行。它正在 Volant 中重写，不再依赖 Python 运行时。目前它解析选项并完成 `ansible-galaxy` 最先做的检查，然后在子命令的原生版本完成之前拒绝执行。

```sh
volant galaxy collection <download|init|build|publish|install|list|verify> [OPTIONS]
volant galaxy role <init|remove|delete|list|search|import|setup|info|install> [OPTIONS]
```

每个子命令都接受 `-s`/`--server`、`--token`/`--api-key`、`-c`/`--ignore-certs`、`--timeout` 和可重复的 `-v`。`collection download` 和 `collection install` 还接受 `--clear-response-cache` 和 `--no-cache`。未知选项或类型错误的值以 2 退出并打印用法。`volant galaxy --version` 打印 `ansible-galaxy` 的版本信息。

## 最先进行的检查

它们在任何实际工作之前进行，消息和退出码与 `ansible-galaxy` 相同：

| 情况 | 消息 | 退出码 |
|---|---|---|
| `collection install` 同时给出名称和 `-r` | `[ERROR]: The positional collection_name arg and --requirements-file are mutually exclusive.` | 1 |
| `collection install` 或 `download` 两者都没有 | `[ERROR]: You must specify a collection name or a requirements file.` | 1 |
| `-r` 指向不存在的文件 | `[ERROR]: The requirements file '<path>' does not exist.` | 1 |
| `role install` 既没有名称也没有 `-r` | `[ERROR]: - you must specify a user/role name or a roles file` | 5 |
| `role install -r` 的文件不以 `.yml` 或 `.yaml` 结尾 | `[ERROR]: Invalid role requirements file, it must end with a .yml or .yaml extension` | 1 |
| `role list` 时没有任何角色路径存在 | `[WARNING]: - the configured path <path> does not exist.` 每个路径一条，然后 `[ERROR]: - None of the provided paths were usable. Please specify a valid path with --roles-path` | 5 |

当 `collection install -p PATH` 的 `PATH` 之下没有任何已配置的集合路径时，命令先打印 `ansible-galaxy` 的警告：`[WARNING]: The specified collections path '<PATH>' is not part of the configured Ansible collections paths '<paths>'. The installed collection will not be picked up in an Ansible run, unless within a playbook-adjacent collections directory.` Volant 追加在集合路径末尾的运行时自己的 `collections/` 目录不会出现在 `<paths>` 中。

## 从 tar 包安装

`collection install` 原生安装集合 tar 包：`volant galaxy collection install acme-demo-1.0.0.tar.gz -p DIR`。名称和版本取自 tar 包中的 `MANIFEST.json`，而不是文件名。集合安装到 `DIR/ansible_collections/<namespace>/<name>`，没有 `-p` 时安装到第一个集合路径下。只写入 `FILES.json` 列出的文件，每个文件先与其 SHA-256 比对。文件权限为 `0644`，归档标记为可执行时为 `0755`。会落到集合之外的条目会被拒绝，指向集合之外的链接也会被拒绝。安装失败不会留下写了一半的集合。输出、消息和退出码与 `ansible-galaxy` 相同。已安装相同版本的集合会得到 `Nothing to do. All requested collections are already installed. If you want to reinstall them, consider using `--force`.`，`--force` 会覆盖旧目录重新安装。`PATH/ansible_collections` 已存在时，`-p` 的警告会说该路径 `appears to be part of the pip Ansible package`，与 `ansible-galaxy` 一致。

目录、URL、git 和签名在原生实现之前都会被拒绝：`[ERROR]: volant galaxy collection install from a directory, a URL or git is not supported yet`，或 `with signatures`，退出码 1。

## 从 Galaxy 服务器安装

`collection install` 也接受名称，需要时可带版本范围：`demo.base`、`demo.base:1.0.0`、`"demo.base:>=1.0.0,<2.0.0"`，以及 `-r` 中的条目。每个名称连同其依赖一起针对服务器解析，每个依赖取满足所有所需范围的最高版本，两个范围冲突时回溯。预发布版本只在使用 `--pre` 或被精确指定时才计入。每个 tar 包先下载，再与服务器给出的 SHA-256 比对，然后按上文解包。从服务器安装的集合还会得到 `ansible_collections/<namespace>.<name>-<version>.info/GALAXY.yml`，记录其来源。已安装且版本合适的集合会被保留：`'<name>:<version>' is already installed, skipping.`

`-n` 跳过依赖，`-U` 把已安装的集合升级到范围内的最新版本，`-f` 重新安装所请求的集合，`--force-with-deps` 连同其依赖一起重装，`-i` 在安装失败后给出警告并继续，`--offline` 不访问任何服务器。当没有一组版本能满足所有范围时，命令以 `ansible-galaxy` 的消息失败，该消息列出各个范围，并以关于 `--pre` 的提示结尾；`ansible-galaxy` 在提示之后打印的 Python 对象被省略。

## Galaxy 服务器

服务器取自 `-s`，否则取自 `ansible.cfg` 的 `[galaxy] server_list` 和 `[galaxy_server.<name>]` 节，再否则取自 `GALAXY_SERVER`，默认是 `https://galaxy.ansible.com`。每个 `ANSIBLE_GALAXY_*` 环境变量优先于文件。每个服务器接受 `url`、`token`、`validate_certs` 和 `timeout`。`--token` 优先于文件中的令牌，`-c` 关闭证书校验，`--timeout` 设置等待时间，默认 60 秒。无法访问的服务器会以 `ansible-galaxy` 的警告跳过，并询问下一个服务器。

令牌以 `Authorization: Token <token>` 发送，从不打印。没有令牌时会读取令牌文件 `GALAXY_TOKEN_PATH`，默认是 `<ANSIBLE_HOME>/galaxy_token`，缺失时以 `0600` 权限创建空文件。代理取自 `https_proxy`、`http_proxy`、`all_proxy` 和 `no_proxy`；`ansible-galaxy` 按 URL 的协议选择变量，而 Volant 对所有 URL 使用第一个已设置的变量。响应在 `<ANSIBLE_HOME>/galaxy_cache/api.json` 中保留一天，与 `ansible-galaxy` 使用同一个文件。`--no-cache` 不使用它，`--clear-response-cache` 清空它。不读取 `username`、`password` 和 `auth_url`。

## 依赖文件

`-r` 按 `ansible-galaxy` 的方式读取依赖文件：同一个文件中的 `collections:` 和 `roles:`，或旧式的纯角色列表（只有 `role install` 接受）。`include:` 条目引入另一个文件中的角色，其路径相对于工作目录。`-r` 给出两次时以最后一次为准。文件中没有该命令的条目时，`collection install` 和 `role install` 打印 `Skipping install, no requirements found` 并以 0 退出。`-vvv` 会先打印 `Reading requirement file at '<path>'`。格式错误的文件以 `ansible-galaxy` 的消息失败，退出码 1：没有条目、出现 `collections` 和 `roles` 以外的键、角色条目既无 `name` 也无 `src`、集合名不是 `namespace.name` 且不指向任何内容，或 `type` 未知。

## 被拒绝的子命令

尚未原生实现的子命令以 `[ERROR]: volant galaxy <subcommand> is not supported yet` 失败，退出码 1。`collection publish` 以及 `role delete`、`search`、`import`、`setup` 和 `info` 需要 Galaxy 账号或服务器的角色数据库，会一直被拒绝：`[ERROR]: volant galaxy <subcommand> is not supported`，退出码 1。

`volant runtime install --collections` 仍使用运行时自带的 `ansible-galaxy` 安装集合。
