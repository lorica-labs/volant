Volant 使用 `ansible-playbook` 使用的退出码，所以为 Ansible 编写的脚本和 CI 任务可以继续工作。

## 各个退出码

<Option name="0" id="code-0">
  每台主机都没有失败地完成了。
</Option>

<Option name="1" id="code-1">
  一般性错误：找不到 playbook 或 role、未知的 `notify` 名称或 `meta` 动作，或者主机模式没有留下任何主机。
</Option>

<Option name="2" id="code-2">
  至少有一台主机失败，或者运行要求使用本版本尚不支持的提权方法。
</Option>

<Option name="4" id="code-4">
  至少有一台主机不可达，或者 playbook 在运行前就停止了：它无法解析，或者用到了本版本尚不支持的内容。
</Option>

<Option name="5" id="code-5">
  某个设置的值不被允许，例如 `forks = many`、`gathering`、`runtime` 或 `host_named_paths` 的未知取值，或者 play 不认识的 `order` 关键字。消息中会写明键和值。
</Option>

<Option name="6" id="code-6">
  一些主机失败，一些主机不可达：2 与 4 的组合。
</Option>

<Option name="99" id="code-99">
  Ctrl-C 或 SIGTERM 停止了运行。正在运行的批次会被取消，汇总会打印出来，Volant 以 99 退出，与 `ansible-playbook` 一致。
</Option>

<Option name="250" id="code-250">
  `--step` 发现标准输入上没有终端。Volant 在接触任何主机之前就停止。
</Option>

## 运行之后

运行结束后，退出码由汇总得出：有任何主机失败时加 2，有任何主机不可达时加 4。`serial` play 会在第一个失去所有存活主机的批次处停止，如果它们是失败，退出码为 2，如果都变成了不可达，则为 4。

## 运行之前

被[预检](/zh-cn/docs/internals/preflight/)拦下的 playbook 会在任何连接之前以 4 退出，这与 Ansible 对无法加载的 playbook 使用的退出码相同。退出码在 Ansible 上测得过的情形保持该退出码：role 缺失、未知的 `meta` 动作或未知的 `notify` 名称为 1。动态 include 引入的文件中的未知 `notify` 名称只有在运行期间才会发现，同样会在那里以 1 结束运行。

## Ansible 崩溃的地方

在少数情况下，ansible-core 会以退出码 250 崩溃，例如遇到导入自身的 playbook，或 `serial: abc`。Volant 则会拒绝这些情形，给出清晰的消息，并使用上面的某个退出码。每种情形都列在涉及它的那一页的*与 Ansible 的差异*之下。

## 其他命令

`volant adhoc`（`ansible`）在每台主机都成功或被跳过时退出码为 0，有主机失败时为 2，有主机无法到达时为 4，`-l` 没有留下任何主机时为 1，设置无效时为 5。`volant vault`（`ansible-vault`）和 `volant inventory`（`ansible-inventory`）成功时退出码为 0，出现错误（例如对已存在的文件执行 `create`）时为 1，选项或动作错误时为 5。它们中任何一个的用法错误退出码都是 2。表格见[ansible 命令名](/zh-cn/docs/start/ansible-command-names/#退出码)。
